# 📢 알림(Notification) 도메인 구축 가이드 및 기획서

---

## 1. 도메인 도입 배경 및 필요성

* **호스트 피드백 부재 해결**: 기존에는 숙소 등록 심사 후 반려(`REJECTED`) 상태가 되어도 호스트가 이유(`REJECT_REASON`)를 즉각 확인할 방법이 없어 관리자 문의로 이어지는 비효율이 발생했습니다.


* **사용자 경험(UX) 및 실시간성 강화**: 관리자의 신규 숙소 심사 대기 건, 호스트의 예약 접수 건 등 주요 이벤트 발생 시 즉각적으로 인지할 수 있는 피드백 창구가 필요합니다.


* **DB 스키마 변경 최소화**: 정규화된 신규 알림 테이블 추가 없이, 기존 엔티티(`ACCOMMODATION`, `RESERVATION`)의 상태값을 조합해 읽기 전용 알림 형태로 신속하게 서빙하도록 설계되었습니다.



---

## 2. 현재 구현 완료 사항 (Current Implementation)

* **도메인 격리 및 통합 DTO 설계**:
* `NotificationDto`를 생성하여 숙소 반려, 신규 예약, 심사 대기 등의 다양한 알림 유형을 단일 규격(`id`, `title`, `message`, `type`, `createdAt`)으로 표준화했습니다.


* **권한별 맞춤 알림 집계 서비스 (`NotificationQueryService`)**:
* **숙소 관리자 (`ROLE_HOST`)**:
* 본인 소유의 숙소 중 반려 상태(`REJECTED`)인 건 조회 및 `REJECT_REASON` 노출


* 본인 숙소에 접수된 신규 예약 내역(`RESERVATION`) 연동




* **총괄 관리자 (`ROLE_ADMIN`)**:
* 신규 등록 후 심사 대기 중인 숙소(`PENDING`) 목록 집계






* **알림 조회 API 엔드포인트 (`NotificationController`)**:
* `GET /api/v1/notifications`: JWT 토큰을 기반으로 사용자 권한을 자동 식별하여 알림 목록 반환




* **프론트엔드 종 모양 UI 및 인터랙션 (`HomePage.tsx`)**:
* `ROLE_HOST`, `ROLE_ADMIN` 권한 로그인 시에만 헤더 프로필 우측에 종 모양 아이콘 표시


* 읽지 않은 알림이 있을 경우 아이콘 좌측 상단에 레드 닷(Badge) 표시
* 아이콘 클릭 시 알림 팝업 토글 및 개별 알림 삭제(`X` 버튼) 기능 지원
* **로컬 스토리지 연동**: 별도의 DB 플래그 없이 브라우저 `localStorage`에 삭제된 알림 ID(`dismissedNotiIds`)를 저장하여 새로고침 시에도 삭제 상태 유지



---

## 3. 차후 구현 필요 사항 (Backlog & Future Work)

* **영구 읽음 처리(DB화)**:
* 현재는 `localStorage` 기반으로 닫기 처리를 수행하므로, 다른 기기나 브라우저에서 로그인 시 동일한 알림이 다시 노출되는 한계가 있습니다.
* 추후 `NOTIFICATION` 테이블 구축 또는 회원별 읽은 알림 이력 테이블 추가 검토가 필요합니다.


* **실시간 푸시 알림 (SSE / WebSocket 도입)**:
* 현재는 페이지 진입/새로고침 시 HTTP `GET` 요청으로 알림을 불러오는 폴링 방식입니다.
* 관리자가 숙소를 반려하거나 고객이 예약을 완료하는 즉시 화면 새로고침 없이 뱃지가 갱신되도록 SSE(Server-Sent Events) 또는 웹소켓 연동이 요구됩니다.


* **알림 클릭 시 상세 페이지 라우팅**:
* 반려 알림 클릭 시 숙소 수정 페이지로 이동, 예약 알림 클릭 시 예약 관리 페이지로 즉시 이동하는 딥링크(Deep Link) 연동 기능이 추가되어야 합니다.
